# DSH Reins · 缰绳

**让 Agent 放手去跑，方向始终握在你手里。**

白天上班，晚上 Vibe Coding。想做的项目一大堆，能抽出来的时间却不多。

**DSH Reins** 是我给 DeepSeek Harness（DSH）做的一个小插件：Agent 自己维护任务树，你随时能看清**最初想做什么、现在正在做什么、已经做到哪了**。Git、代码变更、交付文件和子智能体的信息，也都放在同一个小面板里。

**当前代码版本：v0.3.4 · DSH ≥ 0.2.0-rc.2 · 中文 / English**

> 📸 **真实演示即将补上。** 接下来会开一条新的 DSH Session，用真实开发任务展示 Agent 如何建立任务、推进工作、处理新问题，以及如何在需求变多时回看目标。不是手工摆出来的“理想任务树”。

## 为什么做「缰绳」？

我是个平时要上班、空下来又特别想折腾开源项目的开发者。

今天突然想到一个功能，让 Agent 帮忙写；明天又冒出另一个点子，再开一个项目。工作一忙，可能三五天都没空管自己的仓库。

等终于能回来继续开发，最常见的第一句话就是：

**“等下，我上次做到哪了？接下来要干什么？”**

而且，我没那么多时间亲手写完每一行代码，再逐行 Review。很多时候是 Agent 写代码、Agent Review、Agent 修问题。

这当然很爽，但也有另一面：开发过程中和 Agent 聊着聊着，突然又冒出几个新功能；它发现 Bug，顺手想重构，再讨论两轮又换了一个方案……每件事好像都有道理，可做着做着，你甚至忘了**最初到底想解决什么问题**。

**“不是，我们一开始有打算做这么多吗？”**

我想把重复劳动交给 Agent，但不想把项目方向也稀里糊涂地交出去。

DSH 叫 **Harness（马具）**，那我就把这个插件叫 **Reins（缰绳）**。

马可以跑得很快，不需要你替它迈每一步；但你得知道它跑到了哪里，也得能决定接下来往哪走。

**这就是 DSH Reins 想做的事：让 Agent 负责执行，让开发者始终看得清、接得上、把得住方向。**

## 你可能也遇到过这些情况

### 🕒 好几天没碰项目，一回来就失忆

不用先翻几十轮对话，猜当时在做什么。

打开任务树，看看当前目标、正在做的任务、已完成的部分和下一步。隔几天回来，至少有个清晰的地方帮你重新接上进度。

### 🧭 聊着聊着，需求越做越偏

Agent 很会执行，也很会沿着讨论继续扩展。但**新建议是不是值得做**，应该由你决定。

任务树里有层级、执行焦点，也保留**原始目标、当前目标和修订记录**。发现任务越长越多时，抬眼就能问自己：

- 这件事和最初目标有什么关系？
- 我们是什么时候决定加上它的？
- 这是必须做的，还是聊着聊着顺手加的？

它不是一个能百分之百阻止 Agent 跑偏的“自动刹车”，而是让方向变化**有迹可循、容易被你发现**。重要目标变更仍需要你确认。

### 🤖 Agent 负责干活，不用我再维护一份 Todo

提出需求后，Agent 可以通过工具创建任务、调整层级、更新进展和执行焦点。

开发中发现值得单独追踪的 Bug，可以挂在对应任务下面；不用继续的任务能归档，之后需要还能查到、恢复。已完成任务后来发现新问题，也能追加后续工作，不抹掉之前的完成记录。

**不过，“做完了”不等于“验收通过”：正式标记完成需要你确认。**

### 🔍 不光看它说了什么，还能看它实际改了什么

除了任务树，面板里还可以直接看：

- **Git**：仓库、分支、最近提交与工作区状态。
- **Diff**：哪些文件有未提交改动，点开看具体差异。
- **交付文件**：这轮 Agent 产出了什么。
- **子智能体**：有哪些 Agent 在分工，可以跳转查看。
- **来源**：搜索、网页、文件与工具调用的线索。

不用在聊天、终端、Git 页面之间来回切换。

## 它用起来是什么样？

你照常给 DSH 提需求，不需要额外维护任务清单：

> 帮我实现登录模块，补齐测试。

Agent 开始开发时更新任务树、标记当前焦点；如果后面发现 Token 过期的 Bug，可以加在登录功能下面。聊到“要不要顺便做第三方登录”时，也可以对照当前目标决定是不是该扩范围。

```text
登录功能                         已完成
├── 登录接口                     已完成
├── 登录测试                     已完成
└── 修复 Token 过期问题           进行中  ← 当前焦点

原始目标：完成基础登录功能
当前目标：完成登录功能并修复已发现的问题
```

*上面只是帮助理解的示例，不是插件真实运行截图。*

任务完成时，Agent 等你验收后再更新完成状态；隔几天回来，重新打开原来的工作线，也能接着已有任务进度继续。

> **关于工作线：** 普通新会话各有独立任务树；同一根会话的分支共享工作线。插件**不会**自动把你所有项目和所有会话合成一棵全局任务树。

## 安装

推荐从 **DSH 自定义插件市场**安装：

1. 在 DSH 的插件设置中开启**自定义插件市场**。
2. 进入 **发现 → 添加索引源**，填入：

   ```text
   https://raw.githubusercontent.com/mchenziyi/dsh-summary-panel/main/site/index.json
   ```

3. 刷新市场，搜索 **DSH Reins / 缰绳** 并安装。（如果市场名称还没同步，暂时搜索 **Summary Panel / 摘要面板**。）

也可以在 DSH 插件管理器中使用 [GitHub 仓库](https://github.com/mchenziyi/dsh-summary-panel) 作为 Git 安装来源。市场索引中的正式版本会锁定具体 Git 提交，而不是直接跟随浮动的 `main`。

**要求：DSH ≥ 0.2.0-rc.2。**

## 不用改变原来的工作习惯

插件就在 DSH 会话右上角，需要就展开，不需要就收起，不挤占聊天正文。

任务树由 Agent 通过 `task_tree_read` / `task_tree_write` 更新，面板负责展示；Git 和 Diff 是只读查看，插件不会替你提交、切换分支或推送代码。

它也不是一个“全自动项目经理”：任务记录是否准确，仍取决于 Agent 的维护行为。插件有提示和动态提醒机制，但重要目标变更以及最终验收仍由你把关。

## 想了解更多实现细节？

<details>
<summary><strong>任务树怎么保存、怎么恢复？</strong></summary>

- 支持多层任务、执行状态、焦点、进展和历史记录。
- 取消任务可归档；Agent 可以按需查询归档记录，也可以恢复任务。
- 父任务完成后允许追加新子任务，例如后续发现的 Bug；原完成事实仍保留。
- 数据按工作线保存在本地 DSH 数据目录的 `agent-task-tree` 下（存在 profile 目录时优先放在其中），支持重启后继续读取。
- 普通新会话独立；同一根会话的分支共享工作线。
- 任务树并非强制阻断 Agent 执行，主要依靠工具、提示词和每轮提醒维护。

</details>

<details>
<summary><strong>面板还有什么功能？</strong></summary>

- Git：当前仓库、分支、最近提交和工作区状态，只读。
- Diff：查看未提交修改，支持统一与并排视图。
- 交付文件：查看本轮产出和变更文件，按宿主能力跳转预览。
- 子智能体：展示和跳转子会话。
- 来源：展示网页、搜索词、文件和工具调用线索。
- 中文 / English，跟随宿主明暗主题。

</details>

插件提供 `ctx.summaryPanel.register(...)`，其他客户端插件可以按既有接口增加自己的面板分区。

本地测试：


> `summary-panel` 仍是当前代码与兼容性标识，不影响产品展示名使用 DSH Reins。

## 最后

我做这个插件，不是因为想再造一个任务管理系统。

只是因为**想做的项目很多，能投入的时间太少**。我希望 AI 帮我把想法变成代码，而不是让我每次回来都先花半小时弄清楚：现在做到哪了、为什么做这些、最开始的目标还在不在。

如果你也是白天工作、晚上 Vibe Coding，甚至同时折腾好几个开源项目的人，希望 **DSH Reins（缰绳）** 也能帮你少一点失控感，多一点真正做项目的时间。
