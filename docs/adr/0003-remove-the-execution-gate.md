# 0003. 拆除执行门禁：从「管住 Agent」回到「让人看清」

- **状态**：已采纳（待实施，票见 issue #16–#20）
- **取代**：ADR-0001（「任何改工作区的工具都需要一条 active execution」不再成立）。ADR-0001 记录的那次事故与它当时的推理保留为历史，不再作为现行规则。
- **不再撰写**：原计划的 ADR-0002《Lead 的边界是摩擦，不是能力》。那篇要论证的两条规则（Lead 不得写、Worker 终身一任务）都是门禁的产物，门禁拆除后它们不存在，无需单独记录。它们当时的决断清单留在工作线 `t1` 的进度里。
- **相关代码（删除）**：`host/guard.js`、`host/reservation.js`、`host/journal.js`、`host/reconcile.js`、`host/recovery.js`、`host/lifetime.js`、`host/team-lifetime.js`、`host/binding.js`、`host/roster.js`、`host/caller.js`
- **相关代码（改造）**：`host/model.js`（执行账本 / 冲突 / 强制释放 / dispatch）、`host/tools.js`、`host/prompt.js`、`host/mount.js`、`client.js`（只保留 owner 显示）
- **相关测试**：`test/e2e/scenarios/` 18 → 3（`tree-basics`、`acceptance`、`no-gate`）；`test/tasks.mjs` 删除门禁与执行段；`test/evidence.mjs` 删除证据段、保留验收引用校验
- **词汇**：见 `GLOSSARY.md`。「执行者」的语义从"持有凭证的人"改为"记录里最后标记了在做的人"。

## 背景

这个插件的目的只有一个，写在自己的 README 里：让人回来时**看清**最初想做什么、现在做到哪、下一步是什么（`README.md:7`、`:35`、`:204`）。它的三句话主语都是**开发者**：看得清、接得上、把得住方向。

`README.md:57` 还自己划了边界：

> 它不是一个能百分之百阻止 Agent 跑偏的「自动刹车」，而是让方向变化**有迹可循、容易被你发现**。

三周里，仓库长出了 2245 行执行调度（10 个模块、18 个 e2e 场景、CONTRACT 4 条不变量）。起点是一次真实事故：模型接到「把 README 第一行改成 hello」，自判 *trivial one-off*，不建树直接写盘（ADR-0001 如实记录）。此后每一次补洞都再加一条规则，每一步单独看都合理。

## 为什么拆

1. **服务对象错了。** 门禁管的是 Agent；产品的承诺是给人看见。人类一侧看不到它的任何东西——冲突没有面板 UI（已知限制 8），被拦的人只感到「今天 Agent 怎么这么慢」。
2. **产出与成本不成比例。** 它唯一的产出是"有时返回一段拒绝文案"；为了回答"这个会话认领了没有"这一个问题，挂了账本、认领意图日志、崩溃对账、冲突记录、Worker 台账五套状态。
3. **它有硬上限。** 8 个团队成员 × 终身一任务 = 团队耗尽后无法再干活。实测事故：一张用户截好的图进不了仓库，因为 8 个成员全部用完、无一能再接任务。

## 决策（2026-11-09 与用户逐条确认，共 9 条）

| # | 决定 |
|---|---|
| 1 | `task.owner` **保留**，语义从"凭证"降为"记录"：谁在做只是写上去，不拦任何人 |
| 2 | 老数据**读时忽略、不再写**，不写迁移脚本（顺着契约里「未知字段读取时忽略」那条走） |
| 3 | 提示词改为「**动手前先更新任务树**，并保持进展 / 下一步 / 结果最新」，并把它不做的后果讲给它：*不维护树，用户打开面板就是空的* |
| 4 | e2e 删到 **3 个**，其中一个是**反向反证**（无门禁时 `write` 必须成功），钉住"门禁不许回来" |
| 5 | 版本 **0.4.0**，CHANGELOG 单开 `### Removed` 段 |
| 6 | `§10` 只留**一行原子检查**（同一任务被两个会话同时 claim，第二个被拒），删掉释放 / 交接 / 强制终止的整套仪式 |
| 7 | `claim` / `release` **保留但降为标记**：标记"我在做" / 交还。不再分配执行号、不再校验持有者 |
| 8 | 「只有 Lead 维护任务树」**保留为提示词约定**，删掉代码层拒绝（它与"拆除拦截"直接冲突） |
| 9 | `CONTRACT.md` 从 18 条不变量减到 **11 条**；执行相关字段标 `deprecated` 但保留在结构定义里 |

## 两条写进 review 的宪法

1. **不允许再出现"在工具调用前拦截"的代码路径。** 需要约束行为，写进提示词；写进代码之前先问：它能在面板上被看见吗？
2. **任何新规则必须在面板上有对应的一眼可见物**，否则它只是一层看不见的成本。

## 代价（如实记录）

1. **没有强制之后，任务树可能不被维护**——面板会变空。缓解只有两条：提示词，和"空树在面板上一眼可见"。这是这个产品的本性：它是仪表盘，不是刹车。
2. **两个会话仍可能同时做同一个任务**。只剩那一行 compare-and-set 防同一任务的重复 claim；不同任务改同一个文件仍然没有保护（本版不做文件系统隔离，见已知限制 7）。
3. **三周的开发整层作废，而且它从未发布过。** 0.3.7 之后这批能力（PR #12 / #13 / #14）一直没发版；本版决定不发布、直接拆除。所以用户面没有"行为被撤回"的问题——代价全部落在开发侧：三周工作、2245 行调度代码、18 个 e2e 场景作废。这也说明当时的判断问题不在"拆得晚"，而在"第一次补洞时没人问它属于哪个产品"。
4. **真实进程覆盖面积变小**：18 个 e2e → 3 个。这是接受的代价，因为被删的 15 个测的都是被删掉的那层。

## 被否决的替代方案

**A. 保留 §10 的最小锁（只留领取/释放，删掉证据与对账）。** 否决：用户要的是"不拦"，而锁仍然是拦截的另一半。最终只留下一行原子检查，不保留整套语义。

**B. 拆成两个插件：面板 + Guard。** 否决：Guard 的服务对象不是用户——它没有面板 UI、没有人类可见的价值，拆出去也不会有人安装。它的功能需求本来就不存在。

**C. 只改文档、不改代码（承认现状并把它写成目标）。** 否决：那是让文档替代码圆场。这次盘点发现的病灶恰恰是文档与实现三处互相反转（§3.4 / §11 / §14），第一反应应该是改代码，不是改说法。

## 结果与验证（实施后回填）

- `npm test` 全绿；`npm run test:e2e` 3 个场景全绿，其中 `no-gate` 是长期反证
- 手动验收（步骤见 `docs/testing/manual-acceptance.md`）：① 直接改文件成功 ② 面板照常显示「谁在做 / 已离线」 ③ 任务树仍能建、能推进、能被用户验收 ④ 带旧账本字段的记录能正常显示
- 全仓不再出现"在工具调用前拒绝"的路径
