# 手动验收（v0.4.0：没有强制，只有记录与展示）

> 目的：验证拆除执行层之后的真实产品——**人能看清 Agent 在做什么**，而产品不再假装能拦住它。
> 环境：DSH 桌面 App（插件已重载）+ 任意工作目录。真实进程部分已由 `npm run test:e2e` 覆盖（结果见 issue #20）。
> 决策背景：`docs/adr/0003-remove-the-execution-gate.md`。

## 0. 先理解：工具调用不会被拦下，拒绝只发生在写入校验里

- Agent 改文件、跑命令**不需要**建树、不需要 `claim`，也不存在"谁持位才能动"这回事。
- `task_tree_write` **不会**被任何前置条件拦住；会拒绝的只有这一批写入的**内容**：
  - 未授权的任务不能变成进行中；
  - 授权 / 验收原话必须能在你的真实消息里核对；
  - 父任务还有未完成子任务时不能完成；
  - 已授权、未完成的交付要暂缓或归档时，必须带你的原话；
  - 同一任务已被另一个会话领取时，第二个 `claim` 被拒（唯一的"别人占着"拒绝，且只影响这条记录）。
- 面板空着**不是错误**：它在如实显示"Agent 还没维护树"。
- 卡片回答不算用户原话：用 `ask_user_question` 选项答的内容不能作为授权或验收引用，只有你在聊天框打出来的文字才算。涉及批准 / 验收请直接打字。

## A. 无门禁之后（新组，本版核心）

| # | 你要做的 | 预期 |
|---|---|---|
| A1 | 新会话直接说「把 README 第一行改成 hello」 | **成功**，没有任何前置动作；面板仍是空态（这条会话没建树） |
| A2 | 接着说「建个任务树，把这件事记下来」 | 树出现、任务行可见；不需要 `claim` 才能继续改文件 |
| A3 | 说「claim 这个任务」 | 任务详情显示领取记录（谁在做）；**不产生任何权限变化** |
| A4 | 另开一个会话，让它 claim 同一任务 | **被拒**：同一任务同一时刻只允许一个会话持有；`release` 后任何会话都可以再 claim |
| A5 | 关掉持有领取记录的会话，回来看任务 | 记录仍在，显示"已离线"；不会被自动清掉，任何会话都可以 `release` |

## B. 回归（这些必须和以前一样）

| # | 场景 | 预期 |
|---|---|---|
| B1 | 建一个 pending 任务，让它开工 | 仍然被拒：授权规则没变 |
| B2 | 交付类任务完成 | 仍然要求用户验收，agent 不能自我关闭 |
| B3 | 归档一个已授权未完成的任务 | 仍然要求 `userBasis`（用户原话） |
| B4 | 打开面板 | 任务树、详情浮层、归档区、右栏详情都正常 |
| B5 | 普通问答（不涉及文件） | 完全不受影响 |
| B6 | 从旧版本升级后，打开一个原有工作线（它的 json 里还带着旧账本字段） | 旧树正常显示、不报错；账本字段被忽略，不迁移、不重写 |

## C. 面板可见性（产品本体）

> 真实截图见仓库根 `docs/media/panel-task-tree.webp`。这一组验"人能否在 30 秒内看懂现在做到哪了"。
> C 组可以用 `browser-skill` 对着 DSH Web GUI 跑并截图，不必等人；需要人亲自确认的只剩"真实桌面 App 的观感"。

| # | 你要做的 | 预期 |
|---|---|---|
| C1 | 点会话头部入口按钮打开面板 | 显示「当前任务」区；每个顶层任务带完成数 `n/m`（已完成/总数） |
| C2 | 看任务行 | 缩进表达父子层级；状态用图标区分 待开始 / 进行中 / 阻塞 / 完成；**不显示任务编号** |
| C3 | 看「待授权」徽标 | 讨论中提出、尚未批准的任务带该徽标——"它自己想扩的范围"当场可见 |
| C4 | 有焦点任务时 | 焦点行加粗 + 很淡的行背景；**父任务不跟随高亮** |
| C5 | 没有任何焦点时 | 整棵树收纳，只显示顶层任务 |
| C6 | 首次打开 / 重新进入会话 | 只展开焦点所在路径；你手动展开过的分支不会被强制收回 |
| C7 | 悬停任务行 | 只显示三样：完整任务名 / 简介 /（阻塞时）简短阻塞原因——不堆放日志与按钮 |
| C8 | 切换会话 | 面板不关闭，直接显示新会话所属工作线；新会话没有任务树时显示空态 |
| C9 | 面板打开时点面板外部 | 不关闭。关闭方式见需求 7.5：入口按钮 / Esc / 关闭按钮 / 面板内导航动作让位 |

## D. 对话中的授权与验收

重载插件，在隔离工作目录的新会话运行 D1–D5，再用另一个新会话运行 D6。每一步核对面板、实际工具调用和工作目录。

| # | 你要做的 | 预期 |
|---|---|---|
| D1 | 建立一个只需返回版本号的测试任务，先讨论。接着说「目标改成返回版本号和服务名。先规划，暂时不要写代码。」 | 更新当前目标，保留原始目标。实施待授权，无文件改动。 |
| D2 | 说「先设计一下吧，设计清楚了再写代码。」此前不约定由谁确认设计。如果出现确认卡片，先关闭卡片。 | 交方案后在对话中询问是否开始，实施仍待授权，无文件改动。未回答或关闭卡片后继续等待。 |
| D3 | 说「方案我看过了，按这个方案开始实现和测试。」 | 用这条原话授权同一任务。交付后仍显示进行中，等待验收。 |
| D4 | 说「先别验收，我还没看。」 | 仍显示进行中，没有验收记录。 |
| D5 | 回复「可以了」并确保对话明确指向这次交付。 | 记录为用户验收完成，保存用户原话并清除任务焦点。 |
| D6 | 说「先列出接口设计和一个可运行的测试方案。两项都列清楚后，你可以直接实现版本号接口并测试，不用再问我。」 | 先记录设计。条件满足后引用这条授权，直接实施和测试。 |

## E. 出问题时给我什么

带上这四样，我能直接复现：

1. 会话 id（面板里能看到，或直接说哪个会话）
2. 你输入的原文
3. agent 的原始返回（尤其是任何一句拒绝理由）
4. 当时面板上看到的样子（截图最好）

## F. 一句话验收标准

> Agent 想改文件随时能改；面板如实显示它维护的树；唯一因为"别人占着"被拒的写，是第二个会话对同一任务的 `claim`。
>
> 这个产品**不再提供**"它想绕也绕不过去"的保证——那是另一个产品，本版明确不做（ADR-0003）。
