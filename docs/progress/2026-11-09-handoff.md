## 踩过的坑

- **任务树不在仓库里**：它在 `~/.dsh/agent-task-tree/<根会话 id>.json`，按工作线存储。换一台机器、开一个新会话 —— **面板是空的，这是预期**，不是 bug。工作线记录以本文件与 issue 为准。
- 插件可以被禁用；禁用时工具、提示词、面板一起消失，数据保留，且**没有任何东西会告诉你"你现在没有约束了"**——因为它本来就不是安全边界（`docs/implementation-status.md` 已知限制 6–7）。
- **`REQ:<行号>` 锚点会随需求文档改动漂移**，而且偏移量不统一。改动 `docs/requirements/REQUIREMENTS.md` 之后，必须按锚文本逐条重定位（参考 `git show` 里 `t14` 那次的做法），不能全局平移。
- **`ask_user_question` 卡片里的选择不算用户原话**，不能作为 `approvalBasis` / `acceptanceBasis` / `confirmationBasis`。授权与验收必须由用户在聊天框里打出来。
- 发布新版本 = 改 `package.json` + `CHANGELOG` + 在 `site/index.json` 追加一条并改 `dist-tags.latest`（固定提交号），然后走 PR。
- 团队模式（Agent Team）有 8 个成员上限；不用 Agent Team 时，标准模式下 Lead 直接 claim 任务即可，没有这个限制。
